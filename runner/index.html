Remote runner

A real terminal, when you need one.

Some work needs a JVM, Gradle, Node or a shell. A remote runner provides them, and the IDE connects to it. You host it. Status: {{status:runner}}

01What it adds

  • An integrated terminal with a real shell.
  • A JDK, Gradle, Node, Python and git, so Java and Gradle projects can build and run.
  • Agent command-line tools such as Claude Code or Copilot CLI, which you sign in to yourself, inside the runner.

02How it works

The runner is a small server. When you open a terminal, the IDE connects over a WebSocket and presents your GitHub identity. The server checks it against an allow-list, starts an isolated container for you, and relays a terminal to your browser.

  • Closed by default: it will not start without an allow-list of users or an organization, and an allowed web origin.
  • One container per session, with memory, CPU and process limits, all capabilities dropped, and a per-user volume.
  • Your files move between the IDE and the runner through git.

03Set it up

  1. On a Linux host with Docker, build the image from runner/image.
  2. Start runner/server.mjs with RUNNER_ALLOWED_USERS (or RUNNER_ALLOWED_ORG) and RUNNER_ALLOWED_ORIGINS set.
  3. Put TLS in front of it.
  4. In the IDE run Remote Runner: Set Server URL, then Remote Runner: Open Terminal.

The full guide, with every setting, is in runner/README.md in the source.

04Be careful

A runner gives people a shell. Containers can reach the internet unless you firewall them, and Docker is not a virtual machine. Read the security section before you let anyone you do not trust use it.

The server and the IDE client are tested end to end in local mode. The container image has not been tested in automated builds yet.
