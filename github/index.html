GitHub

Sign in, open a repository, and keep working.

Your edits are saved locally and committed to GitHub for you, including when you close the tab. Status: {{status:github}}

01Sign-in

Sign in uses GitHub's standard OAuth redirect. The site asks for the repo and read:org scopes, so you can open private repositories and organization repositories you can already access.

  • Your access token goes to your browser and stays there. It is never stored on our server.
  • Site owners can restrict sign-in to members of one organization.
  • Sign out removes the token from the browser.

The repo scope is broad. If your organization uses a GitHub App with per-repository permissions, ask the site owner for that instead.

02Workspace

Run GitHub: Open Repository and pick a repository and branch. Next time you open the IDE it returns to the same repository and the same open files.

03Sync

  1. Edits go to a working copy stored in the browser, so typing never waits on the network.
  2. A few seconds after you stop typing, the changes are sent as one atomic commit to the branch you opened.
  3. When the tab is hidden or closing, one last attempt is made.
  4. If anything is still unsynced, the browser asks before the tab can close.

If the branch moved while you were editing and the changes do not overlap, the commit goes on top. If they do overlap, your work is saved on a new side branch and you are told. Nothing is overwritten.

Browsers cannot guarantee background work while a tab closes. That is why sync runs continuously instead of only at the end.

04Limits

  • No merge or rebase tools, and no history browser yet.
  • Very large repositories may not list completely.
  • Commits are made as you; there is no separate bot identity.
